## 1. 引言

### 1.1 编写目的
本文档定义「timer-reminder」定时提醒软件的测试策略、测试范围、测试用例和验收标准，确保软件功能完整、运行稳定，符合需求规格说明书的要求。

### 1.2 测试范围
- 功能测试：4 大功能模块（日常提醒 / 番茄钟 / 闹钟 / 任务）
- 兼容性测试：Android 7.0 ~ Android 14
- 性能测试：启动时间、内存占用、响应速度
- 可靠性测试：后台提醒、异常处理、系统重启恢复
- UI/UX 测试：卡通界面、交互体验

### 1.3 测试环境

| 项目 | 规格 |
|------|------|
| 真机测试 | Android 9.0 / Android 12 / Android 14 各一台 |
| 模拟器 | Android Studio Emulator (API 24 / 28 / 34) |
| 测试工具 | Android Studio Profiler / ADB / Espresso |
| 数据库检查 | Android Studio Database Inspector |

## 2. 测试策略

### 2.1 测试层级

```
         ┌────────────┐
         │ 验收测试    │  ← 用户侧，检查是否符合需求
         ├────────────┤
         │ 系统测试    │  ← 完整功能、兼容性、性能
         ├────────────┤
         │ 集成测试    │  ← ViewModel + Repository + DB
         ├────────────┤
         │ 单元测试    │  ← DAO、工具类、核心算法
         └────────────┘
```

### 2.2 测试类型

| 类型 | 说明 | 负责人 |
|------|------|--------|
| 单元测试 | 对 DAO、ViewModel、工具类进行独立测试 | 开发人员 |
| 集成测试 | 测试 ViewModel + Repository + 数据库的协作 | 开发人员 |
| UI 测试 | 使用 Compose UI Test 测试界面交互 | 测试人员 |
| 功能测试 | 手动 + 自动化测试全部功能场景 | 测试人员 |
| 压力测试 | 频繁创建/删除提醒、同时触发多个闹钟 | 测试人员 |
| 兼容性测试 | 不同 Android 版本和屏幕尺寸 | 测试人员 |
| 后台测试 | 应用关闭/后台时提醒是否正常触发 | 测试人员 |

### 6.2 示例单元测试

```kotlin
@RunWith(RobolectricTestRunner::class)
class ReminderViewModelTest {

    private lateinit var viewModel: ReminderViewModel
    private lateinit var repository: ReminderRepository

    @Before
    fun setup() {
        repository = mockk()
        viewModel = ReminderViewModel(repository, Application())
    }

    @Test
    fun `添加提醒后列表应包含新项`() = runTest {
        val reminder = ReminderEntity(
            title = "测试喝水",
            type = "喝水",
            hour = 8,
            minute = 0,
            repeatType = "每天"
        )
        coEvery { repository.insertReminder(any()) } returns 1L
        
        viewModel.addReminder(reminder)
        
        coVerify { repository.insertReminder(reminder) }
    }
}
```
